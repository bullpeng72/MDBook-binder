이 저장소(또는 현재 작업 디렉토리)는 [mdbook-binder](https://pypi.org/project/mdbook-binder/)로
빌드되는 마크다운 코퍼스다. mdbook-binder는 `pip`/`pipx`로 설치된 별도의 CLI
도구이므로, 이 코퍼스 안에는 mdbook-binder 자체의 소스나 README가 없다 —
아래 규칙은 그래서 파일을 참조하지 않고 이 스킬 안에 직접 담아뒀다. 챕터를
쓰거나 수정하기 전에 반드시 아래 규칙을 그대로 따른다.

## 저작 규칙

1. **각 챕터 파일은 H1(`# 제목`) 하나로 시작해야 한다.** 첫 H1이 섹션 제목·
   URL slug·PDF 표지 제목으로 추출된다. H1이 없으면 파일명 stem이 대신
   쓰여 slug가 지저분해진다. 문서 안에 H1은 하나만 두고, 하위 제목은 H2
   이하로 쓴다 — 전체 도서로 합쳐질 때 모든 헤딩이 자동으로 한 단계씩
   강등되므로(H1→H2, H2→H3…) 챕터 내부 구조는 그대로 유지된다.
2. **이미지 경로는 해당 마크다운 파일 기준 상대 경로**로 쓴다
   (`![](../images/foo.png)` 등). `http(s)://`, `data:`, `file://`, `#`로
   시작하는 경로는 그대로 통과된다. 참조된 파일이 실제로 없어도 빌드는
   멈추지 않고 끝에 누락 목록만 모아 출력하므로, 저작 직후
   `mdbook-binder check <root>`로 미리 확인한다.
3. **Mermaid 다이어그램은 ` ```mermaid ` 펜스 블록**으로 작성한다.
4. **코퍼스 전용 raw HTML(커스텀 다이어그램 등)은 `@@HTML_START@@` /
   `@@HTML_END@@` 블록**으로 감싼다. 그 안에서 쓰는 커스텀 CSS 클래스는
   범용 템플릿에 없으므로 `book.yaml`의 `custom_css`로 별도 선언돼 있어야
   한다 — 새 클래스를 쓰기 전에 코퍼스 루트의 `book.yaml`과 그것이
   가리키는 CSS 파일을 먼저 확인한다.
5. **콜아웃(TIP박스)은 blockquote 맨 앞을 이모지로 시작**해야 인식된다.
   등록된 이모지 목록은 코퍼스마다 다르므로, 챕터를 쓰기 전에 해당
   코퍼스 루트의 `book.yaml`에서 `callouts.tip_markers` 값을 먼저
   확인한다(파일이 없거나 필드가 없으면 기본값은 **빈 목록** — 이 경우
   모든 blockquote가 콜아웃 없이 그냥 일반 인용문으로 렌더된다). 등록된
   이모지가 아닌 것으로 시작한 blockquote도 마찬가지로 일반 인용문으로
   렌더된다.
6. **blockquote 안에 코드블록을 넣으려면 각 줄 앞에 `> `를 붙인**
   ` > ``` ` ~ ` > ``` ` **형태**로 쓴다(일반 코드 펜스를 blockquote 안에
   그대로 넣지 않는다).
7. **관리용 문서(집필 가이드 등 챕터가 아닌 `.md`)는 기본적으로 빌드에
   포함된다** — 기본 제외 대상은 `book.yaml`/`README.md`뿐이다. 챕터가
   아닌 새 `.md`를 추가한다면 코퍼스 루트 `book.yaml`의 `exclude`
   패턴에도 등록해야 한다.
8. **순서 자동 인식을 받으려면 파일/디렉토리 명명 규칙을 따른다**:
   `Part_<로마숫자>_.../Chapter_<NN>_...` 구조를 쓰면 파트·챕터 순서가
   자동으로 잡힌다. 최상위 파일 중 앞자리 번호가 `00_`류(서문)는 파트
   챕터들 앞에, `50` 이상(맺음말류)은 뒤에 자동 배치되고, `Appendix/`
   디렉토리는 항상 맨 마지막에 붙는다. 이 규칙을 따르지 않거나
   `book.yaml`의 `order.files`/`order.manifest`가 이미 순서를 명시하는
   코퍼스라면, 새 챕터를 그 목록에도 추가해야 순서에 반영된다.
9. **URL을 깔끔하게 고정하고 싶은 파일만 `book.yaml`의
   `section_id_overrides`에 파일 stem → slug로 등록**한다(선택). 등록하지
   않으면 H1 제목에서 자동 생성되고, 다른 챕터와 제목이 같아도 `-2`/`-3`
   접미사로 충돌을 자동 회피한다.

## 작업 순서

1. 새 챕터를 쓰거나 기존 챕터를 고치기 전에 코퍼스 루트의 `book.yaml`이
   있는지 확인하고, 있으면 `callouts.tip_markers`·`custom_css`·`order`·
   `exclude`·`section_id_overrides` 값을 실제로 읽어 그 값을 기준으로
   작성한다(위 규칙의 "기본값"은 `book.yaml`이 없거나 해당 필드가 없을
   때만 적용된다).
2. 위 규칙에 맞춰 마크다운을 작성/수정한다.
3. 작성 후 `mdbook-binder check <root>`를 실행해 누락된 이미지, 순서
   해석 결과, 선택 기능 설치 상태를 확인한다. 실제 렌더링 결과까지
   확인하려면 `mdbook-binder build html <root> --out /tmp/preview.html`로
   미리보기를 빌드한다.
